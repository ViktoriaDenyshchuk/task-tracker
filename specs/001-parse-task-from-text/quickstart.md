# Quickstart: Перевірка створення задачі з тексту

Цей документ описує перевірки після реалізації. Межі даних та HTTP-відповіді наведені у [data-model.md](data-model.md) і [контракті endpoint](contracts/post-tasks-parse.md).

## Передумови

- Python 3.11+ та `uv` встановлені.
- Залежності проєкту синхронізовані: `uv sync`.
- Для офлайн-перевірок `.env` і мережа не потрібні.
- Live eval потребує ключа відповідного провайдера у локальному `.env`; ключ не додавайте до команд, звітів чи репозиторію.

## Офлайн тести

```bash
uv run pytest
```

Очікування: усі тести проходять офлайн; нові endpoint тести підміняють `get_parser` і `get_today` через `app.dependency_overrides`. Перевірки покривають HTTP 422 для невалідного тексту без виклику моделі, успішне збереження, присутність у `GET /tasks`, валідацію всіх полів, Europe/Kyiv дату, кожну гілку retry/fallback і збереження поведінки наявних маршрутів. `tests/test_tasks.py` залишається незмінним.

## Live eval

Після наявності ключа провайдера запустіть один із варіантів:

```bash
uv run python evals/run_eval.py --provider openai
uv run python evals/run_eval.py --provider openrouter
```

`evals/run_eval.py` надсилає 8 контрольних фраз через TestClient до реального endpoint, підміняючи `get_parser` на живий parser із обгорткою для лічильника та `get_today` на фіксоване `2026-10-12`. Перевірте поріг не нижче 7/8 і нуль невалідних збережених значень. За потреби збережіть звіт через `--save`; звіт має містити провайдера, модель, дату і результати, але не секрети.

## Ручний API сценарій

Запустіть застосунок локально через `uv run uvicorn app.main:app --reload`, потім надішліть `POST /tasks/parse` з JSON `{"text":"Здати звіт до п'ятниці, терміново #робота"}`. Очікується HTTP 201 з `task`, `path: "model"`, `parsed: true` або контрольований fallback з `path: "rules_fallback"`, причиною і `needs_review: true`. Наступний `GET /tasks` має містити створену задачу. Текст із понад 500 символами, порожній або лише з пробілів має дати HTTP 422 без виклику моделі чи запису.
