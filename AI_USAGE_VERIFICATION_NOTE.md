# AI Usage & Verification Note — POST /tasks/parse

## 1. Використання AI-агента

- **Агент:** OpenAI Codex CLI v0.162.1.
- **Spec Kit:** v1.0.3.
- **Проєкт:** Task Tracker, Python, FastAPI.
- **Функція:** створення задачі з природномовного тексту через `POST /tasks/parse`.
- **Дата підготовки нотатки:** 10.2026.
- **Репозиторій:** https://github.com/ViktoriaDenyshchuk/task-tracker

### Фази SDD

У власній робочій копії послідовно виконано:

1. `specify` — створено специфікацію функції.
2. `clarify` — уточнено невизначені вимоги.
3. `plan` — створено технічний план.
4. `tasks` — сформовано перелік завдань.
5. `implement` — реалізовано новий ендпоінт і тести.
6. `converge` — порівняно реалізацію зі специфікацією, виявлено два зауваження.

Підготовлені checkpoints використовувалися окремо для навчальної демонстрації mutation testing та circular testing, а не для заміни основної реалізації.

## 2. Рішення та виправлення людини

Під час роботи зі специфікацією були уточнені:

- Обробка помилок моделі через `rules_fallback`.
- Один повторний виклик лише для `timeout` і `rate_limited`.
- Валідація дати, пріоритету та тегів до збереження задачі.
- Відповідь HTTP 422 для порожнього тексту або тексту понад 500 символів.
- Нормалізація тегів і підтримка явних хештегів.
- Критерії приймання AC1–AC8 та потрібні докази для них.

Під час `converge` агент виявив дві розбіжності:

- **F1 / T027:** порожній пріоритет `priority=""` помилково замінювався на `medium`. Виправлено, додано регресійний тест.
- **F2 / T028:** немає результату справжнього live eval. Залишено відкритим до налаштування API-доступу.

## 3. Незалежна перевірка розробником

### 3.1. Code review

Порівняно коміти `e65c558` (`04_tasks`) та `2fd1b49` (`05_implemented`).

Результат: 9 змінених файлів, 503 додані та 35 видалених рядків.

Перевірено новий ендпоінт, валідацію полів, retry та fallback. Наявні маршрути `GET /tasks`, `POST /tasks`, `DELETE /tasks/{id}` і файл `tests/test_tasks.py` залишилися без змін.

### 3.2. Автоматичні тести

Команда:

`uv run pytest -v`

Результат після виправлення T027:

**38 passed in 0.15s.**

Середовище: macOS, Python 3.12.3, pytest 9.1.1.

Під час перевірки локального файлу `.env` не було. Тести запускалися без необхідності налаштовувати API-ключ. Окрема перевірка мережевих звернень та змінних середовища не проводилася.

### 3.3. Mutation testing

Використано окрему копію навчального checkpoint `06_mutated`, розміщену в `mutation-test`.

Команда:

`uv run pytest`

Результат: **43 passed, 1 failed.**

Очікувано впав тест `test_past_due_date_goes_to_fallback`.

Причина: у підготовленій мутації видалено перевірку дедлайну в минулому. Тест правильно виявив порушення.

### 3.4. Circular testing

У тій самій навчальній копії виконано:

`PYTHONPATH=. uv run pytest demo/test_circular_oracle.py -v`

Результат: **1 passed, 1 failed.**

- `test_circular_oracle_stays_green` — пройшов, оскільки очікування залежало від тестованого коду.
- `test_independent_oracle_catches_bug` — упав, оскільки незалежне очікування `["робота", "дім"]` не збіглося з фактичним результатом `["Робота", "Дім"]`.

Це показало важливість незалежного тестового еталона.

Після демонстрацій виконано повторний запуск тестів в основному проєкті: **37 passed** до виправлення T027.

### 3.5. Live Eval

Файли `evals/cases.json` та `evals/run_eval.py` наявні.

Справжній live eval на восьми фразах **не запускався**, оскільки окремий API-ключ OpenAI або OpenRouter поки не налаштований.

- Провайдер: не вибрано для фактичного запуску.
- Модель: не перевірено.
- Результат: немає.
- Кількість невалідних збережених значень у live eval: не вимірювалася.
- **AC8: не підтверджено.**

Історичні результати курсових checkpoints не видаються за власне оцінювання моделі.

## 5. Вердикт людини

**Вердикт: умовно прийняти реалізацію для подальшої роботи, але не вважати всі критерії приймання повністю виконаними.**

Підстави: новий ендпоінт реалізований, 38 офлайн-тестів проходять, регресії базових маршрутів не виявлено, а помилка F1 після Converge виправлена.

**Що відхилено:** некоректну обробку `priority=""` до виправлення T027; твердження, що AC8 виконано без реального eval.

**Що залишається відкритим:** T028 / AC8 — live eval із реальним провайдером, оцінювання щонайменше 7/8 фраз і підтвердження нульової кількості невалідних збережених значень.

Подальші обмеження оцінювання: реальні фрази користувачів, інші мови, неоднозначні дати та поведінка різних моделей.

Після виконання live eval нотатку необхідно оновити фактичним провайдером, моделлю, датою, результатами й остаточним вердиктом.
